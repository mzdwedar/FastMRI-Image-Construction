# fastmri-knee: knee MRI reconstruction, packaged and served

A U-Net that reconstructs knee MRI (FastMRI single-coil) from undersampled k-space, plus the production system around it:
model registry and gated promotion, NVIDIA Triton inference, a FastAPI gateway, full observability (metrics, logs,
traces, alerts, SLOs) and CI. It runs on a single host with Docker Compose. Training happens on Google Colab.

## The MLOps picture

The repo covers the whole loop from data to a monitored, versioned model in production.

| Stage | What it does | Where |
|---|---|---|
| Data | Download and split FastMRI knee data by subject | `make data`, `fastmri_knee.data` |
| Train | PyTorch Lightning + Hydra configs; GPU training on Colab, resumable; writes a `run_summary.json` (git sha, hparams, metrics, checkpoint hash) | `fastmri_knee.train`, `notebooks/train_colab.ipynb` |
| Track | MLflow experiments and runs | `mlruns/`, MLflow service |
| Package | Checkpoint to ONNX with a parity check, plus a model card | `fastmri_knee.packaging` |
| Register and promote | MLflow model registry; aliases drive promotion; gates on PSNR, preprocessing version and random-init; one-command rollback | `make register`, `make promote`, `make rollback` |
| Serve | Triton model repository generated from the registry; FastAPI gateway in front | `make sync`, `make up` |
| Observe | Metrics, logs, traces, alerts, latency SLOs, dashboards as code, runbooks | `monitoring/`, `docs/runbooks/` |
| Verify | Lint, typecheck, unit, integration against real Triton, full-stack e2e, nightly benchmark | `.github/workflows/`, `benchmarks/` |

Design and decisions live in [SPEC.md](SPEC.md) and the `SPEC-<module>.md` files; the task list is in
[tasks/todo.md](tasks/todo.md).

## Architecture

```
 client ──HTTP──▶ gateway (FastAPI) ──gRPC──▶ triton ◀── model_repository/ (generated by `make sync`)
                    │ /metrics, logs, OTLP       │ /metrics, OTLP            ▲
                    ▼                            ▼                           │
                  alloy ──▶ loki / tempo     prometheus ──▶ alertmanager     │
                                                 ▲   ▲                       │
                                  node-exporter ─┘   └─ cadvisor             │
                  grafana (dashboards as code)                               │
                  mlflow (registry) ──── `make promote` / `make sync` ───────┘
```

- **Gateway** (`src/fastmri_knee/gateway/`) is torch-free. It validates the upload, preprocesses with numpy
  (`preprocess.py`, shared with training), calls Triton over gRPC and returns the reconstruction.
- **Triton** is the only inference engine. It runs in explicit model-control mode; the model repository is generated from
  the MLflow registry, so what is served is always a registered, promoted version.
- **Model lifecycle:** `register` (checkpoint to ONNX, model card, parity check) then `promote` (gates: PSNR, preprocess
  version match, not random-init) then `sync` (load into Triton). `rollback` restores `previous_production`.
- **Preprocessing version:** the model card records `PREPROCESS_VERSION` and promotion refuses a mismatch.

## Quick start (serving, no dataset needed)

Needs Docker and [uv](https://docs.astral.sh/uv/). Python 3.10 to 3.12.

```bash
make setup                                   # .venv from uv.lock
make api-key                                 # prints a key once; stores only its hash in secrets/api_keys
make up-dev                                  # whole stack; Triton also on :8100 (HTTP) / :8101 (gRPC)
make model-random                            # register an untrained model (random_init) in MLflow
make promote VERSION=1 FORCE=1 ALLOW_RANDOM=1
make sync                                    # load it into Triton

curl -H "X-API-Key: $KEY" -F file=@sample.h5 localhost:8000/v1/reconstructions -o out.h5
```

`make up` is the same without publishing Triton's ports. `make down` stops everything.

| Service | URL |
|---|---|
| Gateway | http://localhost:8000 |
| MLflow | http://localhost:5001 |
| Prometheus / Alertmanager | http://localhost:9090 / http://localhost:9093 |
| Grafana | http://localhost:3000 |
| Loki / Tempo | http://localhost:3100 / http://localhost:3200 |

Copy `.env.example` to `.env` to set `SLACK_WEBHOOK_URL`, `TRACE_SAMPLE_PERCENT`, Triton and gateway resource limits, and the Grafana admin password.

### Gateway API

- `GET /healthz`, `GET /readyz` (no auth)
- `POST /v1/reconstructions`: multipart `.h5` in field `file` (optional demo query `acceleration`), returns `.h5`
- `POST /v1/infer`: raw float32 `N x 1 x 320 x 320`
- `GET /v1/model`: the served model version and card

Everything except the probes needs `X-API-Key`. Overload returns 503 with `Retry-After` rather than queueing without bound. See
[SPEC-gateway.md](SPEC-gateway.md).

## Training

Training runs on a Colab GPU, driven from VS Code. See [docs/training-colab.md](docs/training-colab.md).

1. Put the data on Drive (`make data` downloads and splits it locally: set the signed archive link in `url`, or pass
   `--archive FILE` to `python -m fastmri_knee.data.prepare`).
2. Push a commit and run `notebooks/train_colab.ipynb` at that sha.
3. Download the run folder (`best.ckpt`, `run_summary.json`) and register it locally:

```bash
make register CKPT=best.ckpt SUMMARY=run_summary.json
make promote VERSION=<n> && make sync
```

Locally: `make train ARGS="trainer.train.max_epochs=2"` (Hydra overrides), `python -m fastmri_knee.evaluate`,
`python -m fastmri_knee.predict`. Configs are in `configs/`; experiments are tracked with MLflow (a file store on Drive
for Colab runs).

Data layout: `data/{train,val,test}/*.h5`. Keep splits at subject level to avoid leakage.

## Observability

- One Prometheus scrapes the gateway, Triton, Alertmanager, node-exporter and cAdvisor.
- Alerts: symptom and infrastructure rules in `monitoring/prometheus/rules/`, promtool tests in
  `monitoring/prometheus/tests/`, and latency SLO burn-rate alerts (`/v1/infer` < 500 ms at 99 %,
  `/v1/reconstructions` < 5 s at 95 %). Every alert links to a page in [docs/runbooks/](docs/runbooks/).
- Alertmanager delivers to a local `alert-sink` and also to Slack when `SLACK_WEBHOOK_URL` is set.
- Logs: Alloy ships container stdout to Loki. In Grafana Explore:
  `{service="gateway"} | json | request_id="<id>"` (the id is the `X-Request-ID` response header).
- Traces: gateway and Triton export OTLP to Alloy, which tail-samples (all errors, all requests over 2 s, plus
  `TRACE_SAMPLE_PERCENT` of the rest, default 10) into Tempo. Log lines carry `trace_id`.
- Dashboards (service overview, Triton, infrastructure) are generated code: edit `monitoring/grafana/build_dashboards.py` and run
  `make dashboards`; CI fails if the committed JSON differs.
- `make check-configs` validates Compose, Prometheus config, rules, rule tests and Alertmanager config (needs Docker).

## Testing and CI

| Command | What it runs |
|---|---|
| `make ci` | lint, typecheck, unit tests (no Docker, no data) |
| `make test-integration` | tests against a real Triton container |
| `make ci-e2e` | builds and brings up the whole stack, promotes a random model, runs smoke and observability e2e tests, tears down |
| `make check-configs`, `make hadolint` | config and Dockerfile validation |
| `make bench NAME=cpu` / `make bench-compare` | load-test Triton and compare against `benchmarks/baselines/cpu.json` |

GitHub Actions: `ci.yml` (lint, typecheck, unit, security scans, actionlint, configs), `e2e.yml` (integration and e2e),
`bench.yml` (nightly, advisory).

### GPU (manual check)

Needs a Linux host with an NVIDIA GPU, the driver and the NVIDIA Container Toolkit. It is not run in CI; CI only validates
the Compose file.

```bash
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d
TRITON_PROFILE=gpu make sync     # renders the gpu template (KIND_GPU, ORT CUDA EP) and loads it
make bench NAME=gpu              # compare with benchmarks/baselines/cpu.json
```

Check that `/v2/models/unet_model/config` shows `KIND_GPU`. Batching delay on GPU is 2 ms and unmeasured; record the first
GPU numbers as `benchmarks/baselines/gpu.json` before changing a default.
